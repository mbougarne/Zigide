# Conversation: Clarify Application and Composition Boundaries

## User Raw Input

```text
why we have app and application? It doesn't make sense, there's an ambiguity we should be cleare about our separated
```

## Agent-Normalized Request

- Clarify the intended separation between the `application` module and the executable root currently named `app`.
- Remove the naming ambiguity from source layout, build imports, architecture documentation, ticket evidence, and tests.

## Agent Interpretation

The responsibilities are different and consistent with accepted ADR-0001: `application` contains reusable use cases and service orchestration, while the executable root only assembles those services with adapters and UI. The names obscure that split, so rename the outer module and directory to `composition`, keeping the application-layer responsibility and dependency direction intact. No ADR change is needed.

## Assistant Answer

The distinction is now explicit: `application` is reusable product behavior; `composition` is executable startup and wiring. The executable module, its source directory, documentation, ticket evidence, and tests all use `composition`.
