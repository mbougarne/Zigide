## Agent Interpretation

The maintainer is correct and the repository already said so: `agents/README.md` states "Each substantive prompt that affects the repository gets one Markdown file." Because the merged record was never committed, deleting and replacing it is a pre-publication draft correction, not history rewriting. Had it been committed, the correct move would have been appending dated correction records instead.

The split assigns: the review prompt to record `190aabd3-771f-4abf-be49-c40706d2b86c` (read-only, no artifacts), the fixes prompt to record `dcfdafab-b3a3-4732-a457-0d974ff5bbb7` (owns all file changes from that prompt), and this correction prompt to the present record. The retroactive creation times are stated inside each record. Research records remain `null` for all three because none of these prompts contained AI-process research; the repository rules make research records conditional, not mandatory. If the maintainer wants one research record per prompt unconditionally, `agents/README.md` and `AGENTIC_RULES.md` rule 19 should be amended first so the rule and the practice match.

To make the one-prompt-one-record rule harder to miss, `agents/README.md` now states it as an explicit prohibition on merging prompts.
