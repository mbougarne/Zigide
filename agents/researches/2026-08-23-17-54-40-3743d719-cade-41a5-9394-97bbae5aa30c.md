## Epistemic Boundary

## The Task Shape: Unstructured In, Structured Out

The backlog prompt asked for a transformation from *prose* (architecture documents, a roadmap) to a *structure with hard constraints*: sequential immutable IDs, required fields per ticket, valid dependency references, an acyclic dependency graph, and full roadmap coverage.

A language model generates text one token at a time by sampling from a probability distribution. Nothing in that mechanism natively enforces "IDs are sequential" or "the graph has no cycles" — those are global properties of the whole output, while generation is local. This gap is the central lesson of this interaction.

## Why Large Structured Outputs Need External Audits

A toy model of the risk, with mock numbers: suppose the generator gets any single structured element (an ID, a link, a dependency reference) right with probability `p = 0.995`, independently. For an output with `n` such elements:

```text
P(everything correct) ~= p^n
n =  35  ->  0.995^35  ~= 0.84
n = 300  ->  0.995^300 ~= 0.22
```

These probabilities are illustrative, not measured. The point survives the mock: per-element reliability that feels excellent still compounds into likely global failure as the artifact grows. The conversation record shows exactly this pattern handled correctly — the agent did not trust its own output, but ran audits for ID uniqueness, index/file mapping, dependency validity, and graph acyclicity, then fixed what the audit found (missing terminal newlines, caught by the repository checker).

## Toy Cycle Detection

The acyclicity audit can be understood with a few lines of standard-library Python. The graph is mocked; real ticket IDs are in `tickets/backlog.md`.

```python
mock_deps = {
    "ZIT-001": [],
    "ZIT-002": ["ZIT-001"],
    "ZIT-003": ["ZIT-002"],
    # introduce a cycle to see detection fire:
    # "ZIT-001": ["ZIT-003"],
}

def has_cycle(deps):
    visiting, done = set(), set()

    def visit(node):
        if node in done:
            return False
        if node in visiting:
            return True
        visiting.add(node)
        if any(visit(d) for d in deps.get(node, [])):
            return True
        visiting.remove(node)
        done.add(node)
        return False

    return any(visit(n) for n in deps)

print(has_cycle(mock_deps))
```

Depth-first search with a "currently visiting" set is the same idea a build system uses to reject circular imports — a connection worth keeping in mind for Zigide's own module-boundary ticket (ZIT-007).
