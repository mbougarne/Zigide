# Stream boundaries and evidence boundaries

A pipe read is an arbitrary byte chunk, not a protocol message. For example, a frame header can arrive in four chunks while two bodies arrive in one read. The decoder therefore records partial header/body state and returns a consumed byte count with one owned payload. It allocates a body only after checking the advertised size. A malformed header poisons the connection because searching for a later header could interpret attacker-controlled payload bytes as framing.

Correlation is a separate concern. A response can be syntactically valid but refer to an unknown or already-cancelled request. Fixed pending slots hold borrowed cancellation tokens and monotonic deadlines. Removing a slot on every terminal path and never reusing an ID prevents a late response from applying stale work. Wire validity alone is insufficient evidence that a result is applicable.

Pipe EOF also does not prove process exit. The process may close its output descriptors and continue running. The regression peer demonstrates that distinction, and a deadline must retain the process identity until it can terminate and reap the child. This task inspected the pinned standard-library implementation rather than assuming cancellation behavior from another Zig release.

Verification evidence has similar boundaries. Corpus replay and deterministic generated stress passed; a separate compiler error prevented a coverage-guided campaign from starting. A real ZLS handshake passed after the fake peer tests, detecting a JSON-shape issue those peers did not exercise. These are distinct observations, not interchangeable labels such as “all fuzzing passed.” Finite tests support confidence but do not prove absence of every possible defect.
