# Define ZIT-042 and expose ZIT-043 prerequisite blockers

## Observable problem

A merged toolkit spike does not imply the production editor and its nine journey
dependencies are complete. This task compares explicit ticket/ADR state with the
requested release-like journey rather than substituting spike probes for product
acceptance.

## Educational example: readiness is distinct from correctness

The Zig gate has only two outcomes: blocked and unrun. For nine Done dependencies,
an accepted UI decision and macOS arm64, its answer is still unrun. Changing any
one dependency to Planned, Ready, In Progress, Blocked, Cancelled or Superseded
returns blocked. Tests exercise each transition.

A parser must also scope status to the requested heading: Done in the next
ticket's section or in descriptive prose cannot qualify this ticket. Missing,
unknown and duplicate status fields return errors. This is reproducible through
zig build dependable-editor-test and is not evidence of production behavior.

## Evidence layers and identity

Domain tests can validate transactions while real-filesystem interruption tests
establish only the durability behavior actually observed on that filesystem.
Physical IME and screen-reader observations cannot be inferred from synthetic
composition or accessibility-tree queries. A source revision, dirty flag, build
mode, executable SHA-256 and fixture SHA-256 make a preflight reproducible without
inventing the missing higher-level evidence.

These are general engineering explanations supported by visible files and tests,
not captured attention weights, hidden activations or private model reasoning.

## Limits

The procedure specifies future production evidence; the current tool only inspects
prerequisites. Passing its seven tests does not complete ZIT-043 or qualify the
milestone. No production performance budget or manual observation is fabricated.
