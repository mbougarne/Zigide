# Educational note: undo safety and allocation failure

A reversible transaction owns both inserted and removed bytes. Storage compaction
can therefore replace its internal buffers without invalidating history. The
transaction's candidate text, line index, metadata and selection must all be valid
before publication. Failing any allocation before commit leaves the old state and
redo branch intact. The allocation-failure tests exercise those observable
boundaries rather than guessing about hidden model internals.

The fixed random histories use an independent contiguous-string oracle and owned
before/after states. They test content, scalar/line positions, selection restoration
and branching after each action. Passing a finite seed set does not prove all
possible inputs or physical keyboard/UI behavior. No private reasoning, logits,
weights or hidden activations were observed.
