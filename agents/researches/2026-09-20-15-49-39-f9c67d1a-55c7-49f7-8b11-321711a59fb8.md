# Research: Pilot-to-Fleet Configuration Invariants

A pilot deployment turns a sequence of failures into an accepted configuration. Fleet rollout should copy the complete accepted invariant set, not only the last line changed, because older copies may still contain defects discovered earlier in the pilot.

The repaired reviewer requires four conditions together: a trusted Git checkout at the workspace root, an isolated untrusted head under `source`, a successful ordinary-text result extracted from the execution envelope, and a runtime mode that loads the OAuth credential. Static equality checks then guard against repository-to-repository drift.

For an illustrative calculation, suppose three independent stale defects each stop a run with probability `0.5`. Fixing only the final defect leaves two, so the toy success probability is `(1 - 0.5) * (1 - 0.5) = 0.25`. Repairing all three removes those modeled blockers. The values are not measured GitHub or model reliability; they demonstrate why the unit of rollout is the accepted configuration, not the final edit.

Matching hashes and structural checks prove local consistency. Sama's successful hosted run supplies pilot evidence, but GitHub variables, secrets, and permissions remain repository-specific external state, so Job Board, BZTAM, and Zigide each still require hosted acceptance.
