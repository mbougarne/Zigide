# Why differential testing and benchmark evidence answer different questions

An independently scanning string model is an oracle for a piece-table implementation: after replacing a half-open byte range, both contents and canonical positions should agree. This observed equivalence is stronger than checking descriptors against themselves, but finite generated tests cannot prove all possible sequences. UTF-8 scalar boundaries and CRLF spanning descriptors are useful adversarial cases because the storage representation and text semantics cross at those boundaries.

Timing answers another question. A line-start index can reduce lookup cost while an implementation that rebuilds that index scans the whole document on every edit. The measured 4 MiB workload shows this trade-off; a passing unit test says nothing about whether that edit fits a latency budget. Requested-byte peaks include transient old/new indexes, while retained bytes expose deleted insertion history. Neither metric is process RSS.

Reproducibility requires generated fixture provenance, exact compiler/build mode, hardware context, raw observations, distribution definitions and failure reporting. Replaying four fuzz corpus inputs during ordinary testing is not a coverage-guided campaign.
