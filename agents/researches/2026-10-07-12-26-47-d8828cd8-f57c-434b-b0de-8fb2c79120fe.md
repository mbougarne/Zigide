# Checkpoints separate evidence from remaining work

A useful implementation checkpoint distinguishes prerequisites already merged,
local behavior already tested, and publication checks still pending. A green
local test suite does not establish hosted CI status; a created branch does not
establish that its commit was pushed. Exact commit identities let later checks
be attributed to the code they actually assessed.

Resource cleanup similarly needs exact ownership: a process identifier captured
when starting the process supports targeted cleanup, while a process-name match
could affect another concurrent task. These are observable workflow principles,
not claims about model internals or captured reasoning.
