# Research: Shape Validation Versus Literal Validation

## Epistemic Boundary

This is an educational explanation of repository policy. It does not claim access to private model internals.

## Dynamic Metadata Model

Stable keys can have dynamic values:

```text
human_actor = role + optional identity
agent = platform/provider + model name
```

Literal validation would reject a legitimate Claude, Gemini, or future maintainer record. Shape validation preserves the schema while allowing the actual participants to be recorded honestly. The checker therefore validates required fields and the agent’s parenthesized model form, not one vendor or person.

## What This Record Can and Cannot Teach

It can teach the difference between a data schema and one hard-coded instance. It cannot identify participants that were not supplied in a future interaction.
