# Why safe saving needs more than a successful write

A sibling temporary file separates preparation from commitment. Writing and
syncing that file can fail without truncating the last valid destination. Rename
is the commit point: before it, failures should retain the old disk bytes; after
it, an error must say that replacement already happened. Keeping dirty edits in
both cases provides an explicit recovery path.

Metadata comparison is a conservative conflict signal, not an atomic transaction
with another editor. Comparing again immediately before rename narrows a race but
does not eliminate it. Create-only rename independently prevents Save As from
clobbering a destination created by another process. Native metadata copying
matters because replacing an inode otherwise loses attributes beyond text bytes.

The fixture fails the second bounded write after 4096 real bytes reached the temp
file, then checks original bytes, dirty memory, identity and cleanup. Removing the
fault and saving again demonstrates recoverability. These are observable test
facts, not a simulation of hardware failure. They do not establish power-loss
persistence, and no private model internals are available or claimed.
