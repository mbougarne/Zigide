# Research: Different Review Stages Can Have Different Model Families

## Boundary

The maintainer uses OpenAI models locally for implementation and pre-push review. GitHub sees only the resulting pull request, where Anthropic supplies the hosted review. Removing OpenAI from GitHub automation makes that division explicit and eliminates an unused routing branch.

## Illustrative Calculation

Assume toy defect-detection rates of 0.70 locally and 0.60 in an independently implemented hosted review. With the simplifying independence assumption, both miss with probability `(1 - 0.70) * (1 - 0.60) = 0.12`; at least one detects with probability `0.88`.

These values are invented for explanation, and actual review failures are correlated. The calculation shows why separate checkpoints can be useful, not that any particular model attains those rates.

## Application

The remaining workflow has one model variable and one secret: `ANTHROPIC_REVIEW_MODEL` and `ANTHROPIC_API_KEY`. `AI_REVIEW_ENABLED` remains a separate activation gate. The trust and permission design is unchanged.

## Evidence Limit

Actionlint establishes static workflow validity. It cannot establish live GitHub behavior, Anthropic review quality, cost, or false-positive rate; those require a controlled PR after credential setup.

This describes observable configuration and general verification concepts, not private model reasoning or telemetry.
