# Technical note

An atomic edit transaction prepares every fallible allocation before publishing state. For example, two edits against version 4 are validated in version-4 coordinates, then committed together as version 5. An allocation failure leaves version 4 and its bytes/index/metadata intact. An independently owned snapshot of version 4 can survive either outcome. This is an observable ownership and commit contract, not a description of hidden model reasoning.
