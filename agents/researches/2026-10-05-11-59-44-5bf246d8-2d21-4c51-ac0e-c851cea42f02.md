# Research: Explicit Lifetimes and Observable Verification

## Technical Lesson

A callback can dispose its own subscription and still need its context until it returns. Freeing the context immediately creates a use-after-free. The implemented event scope marks removed subscriptions inactive, skips them on later visits, and releases their contexts only when the outermost dispatch ends. An end-node snapshot also prevents new subscriptions from unexpectedly joining an in-progress dispatch.

Allocation ownership transfers only after registration succeeds. If allocating a node fails, the caller still owns its context and can release it with `errdefer`. After success the emitter owns it and invokes the cleanup callback exactly once. Exhaustive allocation-failure injection checks every allocation boundary, including cleanup after previously successful registrations.

## Small Reproducible Example

This is an explanatory example, not captured model internals: subscribe A then B; A removes B while dispatching. The expected callback sequence is A only, while B's destructor runs after dispatch returns. The repository test named `dispatch order and removal before a callback's turn` exercises that behavior. Run `zig build unit-test` to reproduce it.

Distinct non-exhaustive enum types make an operation ID incompatible with a correlation ID even though both contain a u64. A negative compile fixture validates that contract. Process-local generators remain deterministic and return an exhaustion error instead of silently reusing a value.

A module import proves availability but does not automatically execute that module's tests in Zig. Explicit test roots and actual test counts are stronger evidence than a successful smoke build.
